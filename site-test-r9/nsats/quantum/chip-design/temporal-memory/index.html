Memory and RAM

RAM holds the working data that programs need while they run. NSATS’s technology uses quantum-inspired logic, reversible computing and temporal representation to increase usable memory capacity, lower energy use and improve communication between memory and processing components.

In this section

Memory and RAMInter-memory communication model Placeholder page

Working data in a computing system

A program reads information, carries out calculations and uses intermediate results as it proceeds. Its memory must hold the data needed for those steps and supply it to the relevant processors.

This creates two related requirements: enough usable capacity for the working data, and effective communication between the components using it. NSATS’s memory technology addresses both, connecting how information is represented with how it is accessed and moved.

Working data includes information whose relevance comes from the calculation currently being performed. An intermediate result, for example, may matter because a later step needs it to continue.

A program’s working set is the information it needs during a particular stage of execution. That set can change as the program moves to another stage. In an illustrative spreadsheet calculation, it can include the cells used by a formula and the intermediate values needed to complete it, rather than every sheet in the file. Memory planning must account for the working sets of programs that run together, as well as a program considered on its own.

Increasing usable memory capacity

Physical memory capacity concerns the storage resource in the hardware. Effective capacity concerns the amount of information that resource can hold and supply to a program. NSATS uses temporal representation to increase effective capacity within a given physical memory resource.

For a data-intensive program, the practical interest is the amount of working information it can hold while a task runs. The representation of that information and the way it reaches the processor both affect how memory serves the program.

An analysis program may need input records, temporary calculation space and the result under construction at the same time. A collection that fits into memory by itself may therefore leave insufficient room for the computation that uses it. Temporary space can grow or shrink during the task, so the largest memory demand may occur partway through processing rather than when the program first receives its input.

Communication between memory and processors

A processor requests data from memory and returns results as a program runs. Information may also move between memory regions. NSATS’s connection and transfer processes supply data more effectively to the components that use it.

In an ordinary program, an instruction may request a value whose location is identified by a memory address. Work that depends on that value must wait until it is available. Other independent work may be able to proceed meanwhile. If a program copies information between memory regions, the copy itself requires data transfers even though it does not perform a new calculation on the contents.

The quantum-classical bus carries electrical signals with more than two states, beyond binary 0 and 1. This enables faster processing, data transfer and decision making within a quantum-classical electronic device.

Existing classical RAM works through a specially designed classical chipset or controller added by the licensee and built with the licensed technology. It encodes classical data using quantum-mechanical logic and manages storage and retrieval, so computer buses can send and retrieve the data faster. The RAM itself remains ordinary classical storage. This is not a software-only upgrade or a drop-in change; integration is part of the licensee’s design.

An assessment should consider the running task and these three measures together:

  • Usable capacity — the amount a memory resource can hold.
  • Access time — how long it takes to obtain requested data.
  • Transfer rate — how much data can move over a period.

These measures answer distinct questions about the same running task.

A task that follows a chain of references can need the result of one request before it knows what to request next. Reading a collection in order presents a different pattern: the upcoming locations may already be known. Waiting between dependent requests and moving a stream of available data can therefore affect a task differently, even when the amount of information involved is the same.

Reversible computing and energy use

Reversible operations retain data within the circuit, so an output can be traced back to its input and the input recovered from the output. For memory design, the relevant questions are what information must remain available and how it will be supplied when a calculation needs it.

The combination described at the top of this page addresses memory and the operations performed on its working data together. This supports the lower energy use noted there.

Ordinary software often changes a value in place, replacing what was held at a memory location. A later instruction reading that location obtains the current value. If an earlier stage’s value is still needed, the program must keep it accessible separately or retain enough information to derive it. The requirement includes which version is needed and which part of the program is allowed to change it.

Applications

Large datasets in active use

Data analysis requires information to be available while calculations are performed. Increasing usable memory allows a program to work with more data during a task. NSATS’s communication technology addresses how that working data reaches the processors and how intermediate results are passed back into memory for further use.

In an illustrative analysis of transaction records, a program may group entries by category and maintain a running total for each group. The active memory includes the records being examined, the group identifiers and those accumulating totals. Access is shaped by the calculation: processing the next record may require updating a total located elsewhere in memory. Keeping the dataset available and supplying these scattered updates are distinct demands on the same running analysis.

Scientific and engineering computation

A scientific model or engineering calculation needs working data throughout its execution. Memory capacity influences how much of that information can be held for the task, while access and transfer determine how it is supplied. NSATS’s technology addresses these requirements together in memory designs for demanding computational work.

In an illustrative model of stress in a structure, the program holds descriptions of the material and the parts of the structure being calculated. It also keeps the values used during the current calculation. Some values are read repeatedly; others are replaced as the calculation advances. A memory assessment should follow those different uses through the model’s execution, rather than measure only the size of the initial input.

Memory architecture and licensing

A memory design sits within a larger system of processors, controllers and internal connections. Its implementation needs to account for where information is held, which components use it and how it moves during the intended task.

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips. A licensing discussion can focus on the intended workload, its working-data requirements and the relationship between memory capacity, access and energy use.

A licensee can bring a description of the stage with the largest working set, the data that must be available together and the components exchanging it. It can also state whether the equipment has a fixed memory configuration or allows changes to the installed hardware. These are requirements of the intended system, alongside the software interfaces that an implementation must support.
