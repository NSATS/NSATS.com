Geomagnetism developers

Geomagnetic positioning development begins with a location-dependent task. Define the position information your application needs, then examine how a licensed implementation connects to the device and software that use it.

Understand the positioning role

The technology pages explain how NSATS’s geomagnetic positioning determines location from Earth’s magnetic field, and its intended operating environments: underground, on the surface, in the air, underwater, indoors and in dense urban areas. The implementation pages consider embedded hardware and the interfaces to a wider system. The technology can be incorporated into licensees’ chips, embedded hardware, devices and systems. NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips. Together, these pages help frame the function that an application asks the technology to perform.

An application requirement describes what the software must do for its user. A location-dependent requirement can concern selecting a work record, attaching a place to an event or presenting information during movement. The developer needs to identify the recipient of the location information and the action that recipient performs with it.

Geomagnetic positioning technologies →Geomagnetism implementation →

Device and software roles

An embedded positioning function needs a route to the software that uses its output. The implementation pages explain this relationship through devices, interfaces and application records. Examples include position presented to an operator and position stored alongside an inspection observation.

An embedded function shares the device’s hardware, software and operating context. In an embedded device, the function draws on the same processing time, memory and power as other tasks. Its software must fit when the device is active, idle or asleep; changes to the function can affect the device’s other tasks, and changes to the device can affect the function.

In embedded software, the task obtaining an input and the task presenting it to a user can be separate. One may run while the other is waiting for user interaction. The application needs to decide how those activities relate, including which action causes a displayed value or retained record to change.

Plan an assessment

Choose a representative task and a way to compare position output with a reference. Record the implementation, platform and conditions. The evaluation guidance provides questions to help connect that study with the intended application.

A representative task includes the application action the implementation is intended to support. An operator display can be examined while the operator performs the relevant activity; a record-keeping function can be examined through the information saved and later retrieved. The assessment question identifies what the developer needs to learn from carrying out that work.

A platform is the craft, vehicle or device on which the implementation operates; record its kind, mounting and movement during the task.

Developer documentation

The eight-antenna magnetometer software development kit (SDK) design documentation covers acquisition and equipment operation, separately from the positioning context above. It describes connection and device login, digital signal processing (DSP), calibration, radio equipment self-tests and per-channel averaging. It does not explain how positioning is computed or describe an NSATS hardware product.

SDK design documentation. Draft 2 · 9 October 2026

Read these developer pages in order:

  1. Magnetometer SDK design documentation — the reader index and five manuals, beginning with the walkthrough.
  2. Getting started — the illustrative connection and reading sequence.
  3. Interface reference — logical operations and data records.
  4. Examples and tutorials — illustrative records and averaging arithmetic.
  5. Integration guide — application, session, adapter and device responsibilities.
  6. Software development kit — documentation scope and download.
  7. Versions and compatibility — the document edition and how to interpret its applicability.

The library provides design documentation and reading exercises. It includes no executable software, hardware adapter or measured results.
