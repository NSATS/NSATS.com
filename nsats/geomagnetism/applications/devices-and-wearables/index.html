Consumer devices and wearables

Portable devices are an application direction for geomagnetic positioning, including the intended directions of indoor and dense urban use. A manufacturer can incorporate a location input that serves a user’s task within a device designed around size, power and usability requirements.

On this page

  1. Begin with the user’s task
  2. Fit within the device
  3. Location within the user experience

Begin with the user’s task

A device can use location to present information or associate an activity with a place. The intended experience should define the useful position detail and frequency of position updates. This helps distinguish the value of the positioning function from the other software and services the device needs.

A portable application can respond to an explicit user action or carry out a task while the user does something else. Marking an activity for later review and maintaining a current display are different interactions. The application requirements should identify which action the user initiates, what information the device presents and when the user expects the interaction to finish.

Fit within the device

The technology can be incorporated into a licensee’s chips, embedded hardware and devices. NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips. A licensee’s implementation should be assessed against its hardware, power budget and operating environment. Integration also concerns how position information reaches the application and how the application communicates its meaning to the user.

Position information reaches the application through a defined exchange with the device’s software, which associates the received output with the user’s current task.

A power budget is the allocation of available electrical energy or power across the device’s functions. The display, processing and communications can each contribute to the device’s demand. A portable-device brief can describe the pattern of use: periods of active interaction, waiting and background work. That pattern is part of the manufacturer’s design requirements for the complete device.

Location within the user experience

The application turns position into information the user can understand. For a manufacturer using geomagnetic positioning, the task has to fit alongside the device’s size, power and interface requirements. Those requirements define the implementation context.

In an illustrative activity-recording application, a user marks where a particular part of a walk began and adds a short note. When reviewing the activity, the user needs to recognise the marker’s meaning, not merely see a location. The application can associate the place with the chosen activity and note so that the saved entry answers the user’s later question.
