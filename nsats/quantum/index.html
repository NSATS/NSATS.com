NSATS Quantum

NSATS develops gate, bus and processor intellectual property inspired by quantum mechanics to increase the speed of data processing in classical electronic systems. Its gate designs depart from conventional binary computation, using quantum-encoded representations of data. Bridges connect these representations with classical binary data, allowing the gates to be integrated into existing devices through specially designed classical hardware.

Computation, memory and data movement

NSATS’s computing technologies address processing, storage, working memory and communication as connected requirements of system design. Quantum-encoded data can be compressed, while NSATS’s reversible gates enable faster processing of data transactions. Through an added chipset or controller incorporating the technology, existing RAM processes data faster and existing hard drives retain more information within the same physical storage resource. Quantum-classical network cards provide higher throughput between systems. Internal buses use quantum encoding to represent more information without increasing the physical width of the interface.

The contribution to overall performance depends on the workload and how the technologies are incorporated into the system. An assessment must distinguish the information retained in storage, the working data required during execution and the exchanges needed to complete the task. The pattern of access also matters: sequential processing of a dataset and repeated retrieval of individual records impose different demands on memory and communication. These requirements inform the selection and integration of the relevant technologies.

Technology

NSATS’s computing technology covers:

Quantum-Classical Computing

NSATS’s Quantum-Classical Computing architecture is founded on quantum mechanics, reversible computing and information theory. These foundations support enhancements to existing machines in data centres, computing environments, networks and personal devices, while retaining the surrounding infrastructure and established supply chains.

The hardware implementation of NSATS’s Quantum-Classical Computing methods uses purpose-designed classical chipsets. Integrating these chipsets into existing equipment involves determining which computational functions they perform and how they exchange information with the surrounding processors, memory and communication paths. The division of functions between software and specialised circuitry depends on the application. Assessment therefore encompasses the computational methods, their hardware implementation and the interfaces required to incorporate them into the wider system.

Reversible Computing

NSATS has achieved non-thermal reversible computing at component level: its swap gates retain input and output information and work reversibly in a limited form. An in-built memory uses the retained information to regenerate earlier inputs. Full reversibility across the complete system is the subject of continuing research.

Regenerated inputs can be reused in subsequent calculations. The gates apply principles from quantum mechanics to support high-speed parallel processing.

Post-Quantum Security

NSATS’s Post-Quantum Security technology addresses threats that quantum computing poses to cryptographic protection. It uses classical computing methods inspired by quantum mechanics and is designed to protect information during processing, in memory and along internal data paths. Protection therefore forms part of the processor, memory and communication architecture.

Assessment requires a defined threat model covering the information requiring protection, authorised access and the actions the implementation is intended to withstand. These requirements inform decisions about cryptographic key handling, protected processing and access to equipment and software, connecting the security design to its intended operating environment.

Memory and RAM

NSATS’s specialised gates use quantum encoding to represent classical data for storage in memory. Reversible gates provide high-speed retrieval, decoding the stored representation back into classical bits. These gates operate as pass-through elements, using specialised lookups to return the original input directly, without a reconstruction calculation. This arrangement increases usable memory capacity and supports faster data storage and retrieval.

Existing classical RAM incorporates the technology through an added chipset or controller, supporting faster exchanges between memory regions, processors and memory controllers. The technology is designed for lower energy use.

The portfolio also enables a purpose-designed component to perform both retained-storage and working-memory functions. These remain distinct roles: retained storage preserves information for later use, while working memory supplies data to running programs. The component communicates with processors over the quantum-classical bus. This combined component is a separate implementation route; existing drives and RAM retain their respective storage and working-memory roles when used with an added controller.

Chip Design

NSATS’s chip-design IP combines specialised lookup functions and quantum encoding with in-built memory assisted, non-thermal reversible computing. Reversibility operates in a limited form at component level. These functions enable greater processing capability within nanoscale gates and circuits, bringing data representation, retrieval and reversible operations into the gate design.

Its buses and connectors extend this approach to the interconnects between regions of a classical processor. Quantum-encoded streams represent and carry more information than conventional binary streams over an interface of the same physical width. For an existing 64-bit interface, the increase concerns the information represented within the stream, rather than a change to the physical bus width.

The computational architecture uses this additional information capacity within existing byte streams alongside the specialised gate operations. Gate and interconnect designs can be combined in programmable hardware or custom chips, connecting the encoding, internal communication and processing functions within the implementation.

Processors and Internal Buses

NSATS’s gates handle quantum-encoded data as well as conventional binary data. Its processors and internal buses are therefore compatible with both representations, supporting integration with existing binary computing systems.

NSATS’s quantum-classical bus supports faster communication between processors, memory and other components within an electronic device. It carries electrical signals with more than two states, extending the signalling beyond binary 0 and 1. These connections support faster processing and decision making through the exchanges required for computation, memory access and coordination between components. Integration with the processor architecture requires interfaces that accommodate both the data exchanged and the requests that govern its movement.

Data Movement

NSATS’s data-movement technology enables high-speed data transfer through embedded encoders and decoders at participating nodes. These nodes support both classical binary and quantum-encoded bit streams, providing points at which licensees can incorporate encryption layers and other data-handling functions using NSATS IP. Encoding at the sending node prepares information for transfer, while decoding at the receiving node returns it to the representation required for subsequent use.

For transfers between systems, the nodes establish data tunnels: logical connections that carry quantum-encoded information in a form the intervening network handles as classical data. The encoding and decoding functions reside at the participating endpoints, allowing the tunnels to use existing transmission infrastructure without upgrades or additional specialised management along the route.

The complete operation includes preparation, transmission and decoding, together with any encryption applied in the implementation. Its practical contribution is assessed by how quickly usable information becomes available to the receiving application, accounting for each stage rather than transmission speed alone.

Quantum-Classical Networking

NSATS’s Quantum-Classical Networking technology enables high-speed data transfer through quantum-classical network cards installed at both ends of a connection. Specialised chipsets on the cards perform the processing required for transmission and receipt, while the data passes through ordinary routers between the connected systems. The technology supports wired, wireless and optical links, including long-distance connections.

The cards also support conventional classical networking. They manage incoming traffic at packet level and detect quantum-encoded data, providing compatibility with both classical binary and quantum-encoded streams.

Dedicated circuitry on the cards and NSATS’s specialised gates accelerate encryption processing. Quantum-encoded operations increase the amount of information processed within existing data streams. The implementation combines 4,096 rounds of mixed encryption with NSATS-developed key-exchange methods. This architecture is designed to make post-quantum encryption practical within network equipment by accelerating the associated processing.

Temporal Compression

Temporal Compression increases effective storage capacity by compressing quantum-encoded data, with NSATS’s reversible-computing gates contributing to the process. The drive’s physical capacity remains unchanged, while the compressed representation allows it to retain a greater volume of original data. Effective capacity therefore describes the amount of original information represented within the available physical storage.

As a hypothetical illustration, a drive with 64 GB of physical capacity could carry the specification: “Effective storage capacity increases at 5 megabits per second, up to a maximum effective capacity of 128 GB.” The rate describes the increase in effective capacity over time, not the speed of data transfer. The 128 GB ceiling applies to total effective capacity; the drive’s physical capacity remains 64 GB. These figures illustrate the specification format and do not represent measured performance.

For existing drives and RAM, an added, specially designed classical chipset or controller manages the intermediate operations required to store and retrieve the compressed information. This component requires integration with the existing system; the drive or RAM itself remains ordinary classical hardware. The capacity increase depends on the data, the storage device and the arrangement of gates, buses and computational functions within the implementation.

Applications

Applications include:

High-Performance Computing

NSATS’s IP supports High-Performance Computing (HPC) implementations that achieve comparable computational results with fewer processors and less memory and storage than conventional HPC systems. This can reduce equipment costs, with lower heat output providing an additional operational benefit. The technology is also designed for lower energy use. Once the required technology has been integrated, larger datasets can be processed at higher speed without expanding the surrounding supporting infrastructure.

These capabilities support two operational objectives: reducing the resources required for an established workload, or increasing the scope of computation within an existing computing environment. In an illustrative engineering application, a team could compare a wider range of component geometries and operating loads within the available computing time. The resulting analysis would inform the selection of a design for manufacture. Scientific simulation similarly benefits from the ability to examine larger datasets or a broader range of model conditions.

The licensed IP supports a software stack that can be customised to the operations and computational workflow of an application. This provides a means of adapting the implementation to the calculations, data requirements and execution sequence of a particular simulation or analysis. The resulting cost and performance benefits depend on the workload, software configuration and hardware implementation, with comparisons made against equivalent computational scope and required result accuracy.

High-performance computing →

Data-Intensive Computing

NSATS’s temporal-drive technology enables larger collections of data to be retained within a given physical storage resource. The increase is in effective capacity: more original information is represented within the same physical storage. Combined with classical RAM holding quantum-encoded data, this supports applications that require both substantial retained datasets and sufficient working-memory capacity to analyse them.

Reducing the number of drives and the amount of physical memory required for a defined workload can lower the hardware cost of retaining and analysing data. This can make a broader historical dataset economically practical to retain and use, particularly for services that repeatedly analyse growing collections of records. The cost advantage depends on the data, access requirements and complete implementation, including the added chipset or controller.

An illustrative application is the investigation of recurring faults across a fleet of industrial machines. Analysts could examine measurements from multiple machines alongside their operating histories, using a broader collection of records to identify conditions associated with the faults. Faster access and movement of the required records can shorten the preparation of that analysis and make the information available sooner for operational review.

Data-intensive computing →

Temporal Storage

Temporal storage supports archives and systems that accumulate information for later use. Through an added chipset or controller, NSATS’s technology can increase an existing drive’s effective storage capacity to a multiple of its physical capacity. The achievable increase depends on the data, the application and how the technology is integrated; the drive’s physical capacity remains unchanged.

Temporal drives can be integrated into embedded devices as well as data-centre storage systems. In an illustrative research application, measurements from successive experiments could be retained locally by an embedded instrument or held in a data-centre archive for later comparison and reanalysis.

Storage planning must consider the rate at which effective capacity increases, its upper limit and the time required to retrieve stored information. These characteristics need to be matched to the expected growth of the collection and the frequency and urgency of access.

Temporal RAM and Computer Memory

NSATS’s temporal-memory technology expands usable working-memory capacity and supports high-speed access to data during program execution. Through an added chipset or controller, existing classical RAM can accommodate a larger active dataset within the available physical memory. The technology is designed for lower energy use.

An illustrative application is the optimisation of a production schedule. The program holds planning data and intermediate results while comparing possible allocations of equipment, materials and time. Additional working-memory capacity can allow a larger planning model to remain in memory throughout the analysis. Assessment must account for peak memory demand during execution, including intermediate results.

Working memory serves the active computation; retained storage keeps information for later use. These roles remain distinct when provided by the purpose-designed combined component, which is a separate implementation from adding a controller to existing RAM.

Post-Quantum Security

NSATS IP is designed to protect encryption keys against quantum-computing threats. It applies quantum encoding to the keys themselves and combines this with additional encryption and NSATS-developed key-exchange methods. The approach complements AES-256 and other supported encryption methods, extending protection to key material while it is stored, used during computation or exchanged between systems.

This addresses a distinct vulnerability in encrypted applications. A sufficiently powerful quantum computer could compromise vulnerable public-key methods used to establish or exchange encryption keys, exposing information even where the underlying data-encryption method remains strong. The National Institute of Standards and Technology (NIST) has published post-quantum standards for key establishment and digital signatures to address these threats. NIST’s post-quantum standards

Within an application, the data-encryption method and the protection of its keys perform complementary functions. AES-256 protects the application data, while NSATS key encoding and key-exchange methods provide additional protection for the associated keys. Compatibility with existing encryption methods supports integration into established applications and communication workflows.

An illustrative application is the exchange of confidential engineering records between organisations. The participating systems could retain AES-based encryption for the records while incorporating NSATS technology to protect the keys used to store, process and exchange that information.

Embedded and Edge Systems

NSATS IP enables temporal drives, temporal RAM and quantum-classical processors to be combined within an embedded or edge system. The resulting architecture can retain more information and process larger working datasets at higher speed than a conventional classical implementation with comparable physical storage and memory resources. This extends the analysis that can be performed within equipment operating under constraints on space, power and connectivity.

In an illustrative production-line inspection system, a temporal drive could retain a larger history of sensor measurements without increasing the drive’s physical capacity. Temporal RAM would accommodate current measurements, relevant historical records and intermediate results during analysis. The quantum-classical processor would perform the associated comparisons and calculations, supporting a more extensive assessment of operating conditions and faster delivery of findings for production review.

Combining these capabilities allows the application to draw on a broader local evidence base while managing the distinction between retained records and active working data. Selected findings and records can then be transferred to a supervisory system, reducing dependence on immediate transmission of the full dataset for central analysis. The technology is also designed for lower energy use, supporting deployment where power availability constrains the computing resources that can be installed.

Network Transfer

NSATS IP enables high-speed data transfer, allowing larger datasets to reach their destination within a given period and making information available sooner for processing. Organisations can accommodate growing transfer requirements while retaining the transmission infrastructure between the participating endpoints. This limits the infrastructure changes and associated expenditure needed to increase transfer capacity.

Quantum-classical network cards can be integrated into routers, hubs, switches or other devices serving as the two endpoints. Their compatibility with conventional binary traffic allows encoded transfers to be introduced alongside existing communications. Adoption can therefore focus on the connections that require greater throughput, while supporting the organisation’s continuing use of classical networking.

Performance Evaluation

Performance evaluation assesses an implementation against the requirements of its intended application. Comparisons should use a defined baseline, equivalent workloads and the same requirements for result accuracy and data integrity. The assessment must cover the complete task, including the encoding, decoding, memory access and transfers needed to produce usable results.

Relevant measures include task-completion time, memory access time and the rate at which usable data becomes available at the destination. Physical storage and memory capacity must be distinguished from effective capacity, and effective-capacity growth must be measured separately from transfer and retrieval rates. Resource comparisons should account for processors, memory, storage, network cards and any additional chipsets or controllers. Energy use and heat output require separate assessment, while cost comparisons should include the hardware, software and integration required by the complete implementation.

Illustrative examples describe possible applications or hypothetical specifications; they are not measured results. Reported measurements should identify the workload, baseline, input data, hardware and software configurations, and concurrent activity, stating which conditions were held constant. Conclusions should remain within the scope of the tests performed.

Software and Hardware Implementation

NSATS licenses its intellectual property: patents, designs and copyrighted software. Where the licensed IP takes the form of software, NSATS supplies it under the licence. Documentation and all software support are provided for a period of one year from the licence’s effective date, as described under IP Licensing. Each licensee designs and builds its own solution. NSATS does not sell the resulting end products.

The licensee selects and integrates the relevant computational methods, software and hardware designs to meet its operational requirements. Depending on the function, the implementation can use software, programmable hardware or custom chips. Hardware-dependent capabilities require specialised circuitry, including the added chipset or controller used with existing drives and RAM.

The software stack can be customised to the application’s operations and workflow. Software and programmable hardware provide routes for later updates and reconfiguration; changes to a custom chip may require a revised hardware design. Implementation planning therefore includes maintenance, interface compatibility and verification of subsequent changes.

IP Licensing

NSATS licenses intellectual property for incorporation into applications, components, devices and systems. Programming, customisation and integration of the resulting solution remain the licensee’s responsibility. NSATS does not provide programming or customisation services for licensees’ solutions.

NSATS provides support for one year from the licence’s effective date. All support, including the provision of documentation, bug fixes, software updates and upgrades, is limited to this period.

An IP licensing discussion focuses on the application to be developed and the functions NSATS technology would perform within it. An outline of the operating environment, required interfaces and expected results helps identify the relevant IP and the questions that need to be resolved.

The intended use may involve incorporating the technology into an organisation’s own computing environment or into a product supplied to others. Clarifying that use provides a basis for discussing the intellectual property to be included, the permitted uses and the commercial terms of the licence.
