NSATS / Chip Design / Memory and RAM

Inter-memory communication model

Information exchanged between memory and other components is part of the work a computing system must perform. Connections and access patterns affect how that information reaches the operation that needs it. This page describes, at application level, which components exchange information in a licensee’s design, what an exchange carries and what behaviour the licensed technology supports.

Memory and RAMInter-memory communication model

System context

An implementation discussion should identify the components exchanging information and the tasks those exchanges support.

An access pattern describes how a program uses its data over a task. Repeated requests for the same information differ from a pass through a collection whose entries are each used in turn. If several components use shared information, their tasks may also require agreement about which version each component should read.

Communication model

The quantum-classical bus — diagram and explanation

Participating components

Processors request data from memory and return results as a program runs.

Working memory (RAM) supplies data to a running program. Existing classical RAM works through a specially designed classical chipset or controller added by the licensee and built with the licensed technology. It encodes classical data using quantum-mechanical logic and manages storage and retrieval, so computer buses can send and retrieve the data faster. The RAM itself remains ordinary classical storage. This is not a software-only upgrade or a drop-in change; integration is part of the licensee’s design.

For retained storage, the licensee’s added chipset or controller encodes the data and manages intermediate processing when compressed data is stored or retrieved. The drive remains ordinary classical storage.

NSATS’s licensed Quantum technology enables one component to perform both storage and working-memory roles in a solution designed and built by the licensee, while existing drives and RAM remain ordinary classical storage. Retained storage and working memory remain distinct functions with different access patterns. The licensee determines how the roles share the component and how it connects to processors and controllers.

The quantum-classical bus carries electrical signals with more than two states, beyond binary 0 and 1. This enables faster processing, data transfer and decision making within a quantum-classical electronic device. Buses and interconnects carry information between device functions, from memory to a processor or between memory regions. Where one component performs both storage and working-memory roles, the same bus carries its retained-data and working-data exchanges with processors.

Memory-controller designers have a role alongside RAM manufacturers because access to working information depends on the controller as well as the memory.

The internal bus supplies components inside the device; paired quantum-classical network cards handle the separate transfer to another system through ordinary routers.

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips.

The interface at application level

An ordinary digital bus carries signals for data, addresses and requests between components. An address identifies the requested information; the request specifies the action needed. Physical connections and signal-exchange rules form part of the interface. This page describes the interface at application level. Electrical and protocol details belong to the licensee’s design and the documentation supplied under licence.

The communicating components must agree on request completion, which version of shared information to read and which part of the program may change a value needed later.

A program requests information through a software interface. The system translates the request into operations the device accepts, so the application works with requests and returned information rather than every device-level command. A request can be accepted while work continues; submitting it does not establish completion.

With a licence, NSATS supplies licensed software, documentation and updates; the interface contract the licensee builds against belongs in that documentation, rather than on this page.

Supported behaviour

Processor work dependent on a value waits until it is available; independent work may proceed. NSATS’s connection and transfer processes supply data more effectively to the components that use it.

A copy between memory regions requires transfers without calculating anything new from the contents. A measurement counts data delivered to the application separately from all the transfers performed to deliver it.

A chain of dependent requests needs one result before the next request is known. In a sequential pass through a collection, upcoming locations may already be known. Waiting between dependent requests and moving available data affect tasks differently, even with the same amount of information. Assessments consider usable capacity, access time and transfer rate together; these answer distinct questions about the running task.

Internal connections, including the bus, supply retained information for the external processor to regenerate an earlier input. That input must be available to the component performing the later calculation when that stage begins.

Alongside the components and tasks identified under System context, the licensee records the stage with the largest working set and the data needed together. A working set is the information needed at a particular stage. The record states whether storage and working memory occupy separate components or share a component built with the licensed technology, and whether the equipment’s memory configuration is fixed.
