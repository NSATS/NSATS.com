NSATS / Chip Design / Memory and RAM

Memory communication model

NSATS’s memory-communication technology supports the exchanges that supply working data to processors and move information between memory regions. The communication model describes the participating components, the information they exchange and the conditions under which the receiving function can use it. For a system developer, this connects the memory capability to the application’s sequence of work.

The model distinguishes capacity from access and transfer. Additional memory is useful only when the program can obtain the required information, while a faster transfer must still deliver the correct data to the correct operation. These requirements apply to existing RAM with an added controller and to the separate combined storage and working-memory design.

Components and implementation routes

Existing classical RAM incorporates NSATS technology through an added, specially designed chipset or controller. It manages the encoded representation and the operations used to access the working data. Memory-controller designers therefore have a role alongside RAM manufacturers in determining how the information reaches the processor.

Existing drives use an added chipset or controller for intermediate storage and retrieval operations, while continuing to provide retained storage. A separate purpose-designed component can combine retained storage and working memory. The design must identify which role each request serves and how the two uses share physical resources.

The quantum-classical bus connects functions within a device using electrical signals with more than two states. It carries information between processors, memory and other components. Transfers to another system use a separate arrangement: quantum-classical network cards at both endpoints, with ordinary routers carrying the traffic between them.

Requests, data and completion

A memory request identifies the information required and the action to perform. The receiving component must interpret the request consistently with the sender, including the data’s location, format and relationship to the application’s work. The physical connection carries the signals, while the agreed interface defines their meaning and sequence.

The application works through a software interface rather than issuing every device-level command itself. That interface must distinguish an accepted request from completed work and identify an unsuccessful operation. Receiving a response is useful only if the application can determine which request it belongs to and whether the required information is ready.

Where components share data, they also need agreement about which version a calculation reads and when another component may change it. These are requirements of the particular implementation; the public model does not specify electrical signalling rules or a complete device protocol.

Access patterns and dependent work

A calculation that needs a requested value must wait for it before proceeding with dependent work. Independent operations may continue if their inputs are available. A sequence of known memory locations can support a different transfer pattern from a chain in which each returned value identifies the next request.

Copying information between memory regions also consumes transfer resources, even though it does not calculate a new result from the contents. The amount of useful data delivered must therefore be distinguished from all the traffic and intermediate movements required to deliver it. Concurrent tasks can add demands to the same paths and controllers.

Earlier information for later calculations

NSATS’s limited component-level, non-thermal reversible-computing arrangement uses retained input and output information with in-built memory to regenerate earlier inputs. Internal connections make those inputs available to the subsequent calculation that needs them. Full-system reversibility remains the subject of continuing research.

The communication model must preserve the association between the regenerated input and its original operation. It also accounts for the information held while the next stage waits or performs other work. Capacity, access time and transfer rate are considered together, with shared physical memory counted consistently across its different uses.
