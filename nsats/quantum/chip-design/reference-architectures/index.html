Reference architectures

These reference architectures describe how NSATS functions fit into storage, memory, networking and security systems. They identify the work performed by the specialised function, the surrounding components and the information exchanged between them. Manufacturers and system developers can use these descriptions to relate the technology to their own equipment and application requirements.

The configurations explain functional arrangements rather than specify a hardware model, product version or measured performance. The appropriate implementation depends on the selected technology and the system in which it will operate. Software, programmable hardware and custom chips provide different routes, while hardware-dependent capabilities require specialised circuitry.

Storage with an added controller

Temporal Compression increases the amount of original information that can be retained within a physical storage resource. Existing storage incorporates the technology through an added, specially designed chipset or controller that manages the intermediate storage and retrieval operations. The storage medium can include a hard drive, solid-state drive, USB flash drive, optical medium or an array; the required integration depends on the medium and system.

The application identifies the information to store or retrieve through its software interface, while the controller coordinates the device operations. The interface distinguishes work still in progress, completed work and failure. Retrieval checks whether the required original information has been returned intact.

Effective-capacity growth, its upper limit and the speed of storing or retrieving data are separate characteristics. The achievable capacity depends on the data and complete implementation, including the information required for retrieval. It cannot be described solely by the rate at which data passes through the system.

Working memory with an added controller

Existing classical RAM incorporates NSATS’s encoding and memory-access functions through an added chipset or controller. The RAM continues to provide working data to running programs, with the technology supporting greater usable capacity and faster exchanges with processing components. Controller designers and RAM manufacturers contribute to how that access is provided.

The quantum-classical bus carries requests and data using electrical signals with more than two states. The implementation connects this signalling capability to the memory operations required by the program. Usable capacity, access time and transfer rate must support the active workload, including its intermediate results and concurrent demands.

Memory and RAM →Memory communication model →

A combined storage and working-memory component

A separate purpose-designed component can provide both retained storage and working memory. The roles remain distinct even when they share physical resources: retained storage preserves information for later use, while working memory supplies an active calculation. The design determines how requests for the two roles share the component and its connections to processors.

The resource account distinguishes retained storage, working RAM, retained gate information and the processor’s working memory. These are uses of information rather than four mandatory physical devices. Shared capacity must be identified and counted consistently so that combining functions does not imply additional physical memory that is not present.

Networking with paired endpoint cards

The networking arrangement places a quantum-classical network card containing a specialised chipset at each endpoint. The cards process information for transmission and receipt, while ordinary routers carry traffic between the host systems. The architecture supports wired, wireless and optical links, including long-distance connections.

The complete transfer begins with the sending application’s information and ends when the receiving application can use it. The card-to-host paths, memory access and networking software therefore contribute to the result. Channel capacity, the rate of transmitted bits, the throughput of original data and the elapsed time to usable information describe different aspects of that transfer.

Security in software and chip-based systems

NSATS’s Post-Quantum Security uses classical computing methods inspired by quantum mechanics to protect information. Its scope includes data in transit and at rest and, within chip-based systems, information during processing, in memory and along internal data paths. The relevant implementation depends on where the information is used and the threats it needs to withstand.

For browsers and the servers they connect to, the licensed security software runs at both ends of the connection. Larger systems incorporate the security into purpose-designed chips. The protection provided by the complete system also depends on the cryptographic construction, key handling and the surrounding application; the configuration alone does not establish a measured security result.

Reversible functions within an architecture

NSATS’s swap gates retain input and output information, with in-built memory using it to regenerate earlier inputs for subsequent calculations. The gates operate reversibly in a limited, non-thermal form at component level. Full reversibility across a complete system remains continuing research.

An implementation containing these functions must account for the retained information and the connections that supply regenerated inputs to later work. The relevant boundary includes the components needed for the claimed operation, making clear which functions are provided by existing equipment and which are added by the design.

Interfaces and implementation records

Each configuration requires agreement on the information exchanged and what constitutes completion. Storage interfaces identify requested data and returned status; memory interfaces identify the action and information required; network interfaces connect a transfer request to delivery at the destination. The detailed formats, electrical requirements and error responses belong to the particular implementation.

A versioned implementation record identifies the software or hardware version, supported environment, interface specification and verification results to which it applies. The public configurations above do not substitute for that record. The linked compression demonstration describes its own session-based software architecture and should not be treated as documentation of every licensed hardware arrangement.

The project also needs to identify which existing responsibilities continue when a specialised function is added. Connecting each requirement to its responsible component and verification check allows the organisation to examine the complete design, including dependencies on equipment and software outside the added function.
