NSATS / NSATS Quantum / Quantum applications

Temporal storage and memory

NSATS’s temporal compression technology uses concepts from quantum mechanics to store more data within a given physical storage resource. Increased effective capacity also applies to working memory, where running programs need information available.

The quantum-classical bus carries electrical signals with more than two states, beyond binary 0 and 1. This enables faster processing, data transfer and decision making within a quantum-classical electronic device. See Quantum applications for the wider explanation.

Temporal storage

Temporal compression increases effective capacity: more data can be stored or retrieved within the same physical storage resource. The physical size of the drive stays unchanged. Classical data is encoded using quantum-mechanical logic. NSATS’s processor-assisted, semi-reversible computing contributes to compression, so the drive holds more data.

The increase depends on the drive, how the licensee uses the technology and where the licensed gates, buses and computational technologies sit in the licensee’s design. For both existing drives and RAM, the licensee adds a specially designed classical chipset or controller built with the licensed technology. It encodes the data and manages the intermediate operations when information is stored or retrieved. The drive or RAM itself remains ordinary classical storage. This is not a software-only upgrade or a drop-in change; integration is part of the licensee’s design.

Effective capacity depends on processing time, not only physical size. A temporal drive is better described by how much data it can process and store per second than by a fixed capacity.

Uses include retained research datasets, operational records and systems that collect information continuously.

For a retained collection, the application specifies which information belongs in the collection and which requests it must answer. Records may be organised by subject, source or the event they describe. Those choices govern how a user locates relevant material. A storage requirement should include the expected retrieval questions, not only the intention to keep adding information.

In ordinary computing, a drive retains saved information after a program ends or power is switched off. Working RAM in ordinary computers needs power to retain its contents, and a program cannot rely on its working allocation remaining available after it closes. Information needed in a later session must therefore be saved in retained storage.

Temporal RAM

RAM holds information needed during a program’s execution. Greater effective capacity lets a system work with more information within a given memory resource. Through the licensee’s added chipset or controller described above, computer buses can send and retrieve encoded classical data faster. NSATS’s technology connects usable capacity with memory access, communication and reversible computing.

An ordinary running program can need input data, temporary workspace and a result under construction at the same time. Memory demand can overlap when one stage builds a result before an earlier stage releases its working resources.

For an ordinary program, access time is the wait for requested information, a separate consideration from how much memory it occupies.

Continuous collection and active computation

A collection that grows as new records arrive needs storage for information that will be requested later. A running calculation needs working data supplied as it proceeds. These illustrate the two uses of temporal compression: increased effective capacity for retained storage and for RAM.

In ordinary data collection, incoming records need to be accepted or buffered as they arrive. Analysis can usually wait or work on records already stored.

Information may arrive steadily or in bursts when connected equipment submits accumulated records. An application can have quiet periods followed by concentrated work even when its long-term collection rate is stable. Its requirements should describe that pattern and any simultaneous analysis, so the system is specified for the intended use rather than an assumed uniform flow.

Licensed implementation

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips. A licensee’s drive, memory component or wider system incorporates the relevant functions and connects them to the application using the data.

A licensee can bring a description of the retained collections, the questions asked of them and the running programs that use them. Existing equipment, available connections and space or power constraints belong with that description. It should also distinguish components it intends to replace from equipment that must remain part of the system.
