Quantum engineering concepts

An implementation discussion is clearer when capacity, access, processing and transfer are described separately. These concepts explain different aspects of how a system completes its work.

  • Capacity and access

    Capacity concerns how much information a resource can hold or store. Access concerns obtaining the information when it is needed. A larger collection of data available to a running program and a shorter access time would help different aspects of a task, so a memory evaluation should describe both rather than treating them as one measure.

    An ordinary program may have room for its information while still waiting for a requested item. Conversely, prompt access to individual items does not establish that all the working information needed together will fit in memory.

    Temporal Compression stages — diagram and explanation

  • An operation and a complete calculation

    An operation performs a defined transformation. An application may need many operations, intermediate information and exchanges with memory. Assessing the full calculation makes it possible to understand the operation’s contribution and the work required around it.

    An algorithm sets out operations for performing a task. An individual transformation contributes to that sequence but does not define every action the application requires. In an illustrative invoice calculation, arithmetic produces a total while application rules decide which entries belong in that total. The result depends on both the calculation and the selection of the relevant information.

    Processor architectures →

  • Transfer and usable information

    A network transfer begins before data enters the network and ends when the receiver can use it. Preparation, routing, receipt and reconstruction can all be relevant. In the NSATS network design, quantum-classical network cards at both ends of the connection form part of that complete path, and the data passes through ordinary routers in between.

    In ordinary packet networking, preparation divides data into units and supplies addressing information; routing forwards those units towards their destination. Receipt collects incoming units, and reconstruction assembles them in the required order into information the application can use.

    An ordinary application’s receiving program needs to interpret incoming information according to the meaning agreed for that exchange.
