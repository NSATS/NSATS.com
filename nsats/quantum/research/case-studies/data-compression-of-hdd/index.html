Data compression of HDD

data compression on a hard disk drive using NSATS’s developed drive

Summary

This case is built on a synthetic sample — not a measurement — to fix the record’s layout; it is published as a labelled illustration and is replaced by recorded runs as they are approved. The case uses generated inputs and modelled compression rounds to illustrate the sizes, rotation counts and fingerprints a record needs. The tables separate per-test totals from per-round detail, and the figures illustrate how to read the supplied sample rows. It does not establish measured compression, intact retrieval or a drive’s general capacity or processing rate.

What this case aims to show

The case asks what a record needs to document a file being stored on NSATS’s developed drive, processed over successive compression rounds and retrieved intact. It follows the input size, the output carried into each further round, the final stored size and the original and returned fingerprints. The synthetic sample illustrates that record’s layout; it does not answer the question of how the drive performs.

The arrangement

NSATS has developed a specific hard drive using quantum-mechanical logic as its own research and development demonstration of its licensed technology. This case uses the generated CSV input files supplied with the synthetic sample. It contains no log from that drive.

The register’s software-version field reads “SAMPLE”; it is not a recorded software version. A recorded test must identify the hardware configuration and software used.

[DATA — platform and components from an approved drive log]

[DATA — software version from an approved drive log]

The record distinguishes receipt of the input, storage and retrieval. Test labels replace dates and clock times in this case; modelled duration remains a separate field.

The task

The following sequence describes the synthetic sample, not a test carried out on the drive.

  1. Use a generated input file and its supplied size and SHA-256 fingerprint.
  2. Take the number of rounds assigned to that test in the sample register.
  3. Process the input through the modelled rotations for the first round, using the per-rotation input and output entries.
  4. Carry the output into the next round and continue for the assigned number of rounds. Round r+1 processes the output of round r.
  5. Enter the final modelled size, the supplied compression percentages and the total rotation count in the test record.
  6. Use the input fingerprint again in the returned-fingerprint field, as the sample generator does. No restoration took place.

Input size and the number of rounds vary between tests. The rotation rate and per-rotation compression band follow the same supplied model throughout. No file type other than the generated CSV inputs is represented.

How to read the results

Original size is the size before compression. Stored size includes the retained representation and required supporting information within the stated boundary.

In this synthetic sample, the stored-size entry is the modelled output of the final round. The CSVs do not separately account for supporting storage.

[DATA — stored-size boundary and supporting information counted in an approved drive log]

The original and returned SHA-256 fields identify the input and the file returned for comparison. In a recorded test, these would be fingerprints recorded during the run. Here, the original fingerprint is calculated from the generated input file and the returned field repeats it by construction; equality is not evidence of intact retrieval.

In the supplied model, 1K is 1,024 bytes or 8,192 bits. A rotation processes 1K of the data in one second, with a compression figure between 2.5 and 3.1%. A round is a complete pass over the data; a test comprises one to ten rounds. Total rotations equal the modelled test duration in seconds. These are the model’s definitions, not measured drive performance.

Round compression is the reduction relative to that round’s input. Cumulative compression is the reduction relative to the test’s original input after the stated round. Overall compression is that cumulative reduction after the final round. The tables and figures use the percentages already supplied in the CSVs.

The operator-selected compression setting belongs in a recorded test. The sample’s modelled band and round count do not supply that setting.

[DATA — operator-selected compression setting from an approved drive log]

Tests are labelled by number only. The figures use elapsed duration where specified, not a date or clock time.

Limitations

Synthetic rows; no limitations recorded.

What this case does not establish

  • A single run does not measure capacity or processing rate.
  • The sample does not establish compression or restoration behaviour for other file types.
  • It establishes nothing about any licensee’s drive.
  • The repeated returned fingerprints do not establish that a file was restored or retrieved.
