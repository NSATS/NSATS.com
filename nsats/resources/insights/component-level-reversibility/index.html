Why ‘reversible’ is a component-level claim

The decision

Recoverability concerns whether an earlier input can be obtained from the information available. Logical reversibility requires each step within the chosen boundary to preserve enough information to identify the state before it. A recoverable transition may also be reversible, but recovery alone does not establish that all the steps meet this test.

For a licensee assessing an implementation, the boundary can include gates, retained information, the controller, processor and storage, together with transfer where applicable. A smaller subsystem can be considered if its inputs, outputs and external dependencies are explicit. The boundary defines the steps being tested and the resources being counted.

What has been achieved

NSATS has achieved reversible computing at component level: its swap gates retain input and output information and work reversibly in a limited form. An external processor uses the retained information to regenerate earlier inputs, which can then be used in subsequent calculations. Full reversibility across the complete system is the subject of continuing research. NSATS describes this arrangement as processor-assisted, semi-reversible computing.

‘Processor-assisted, semi-reversible computing’ is an NSATS working description, not an established scientific category or a measured degree of reversibility. The presence of a processor does not by itself make a computation irreversible; what matters is how information is preserved through its operations.

White Paper 1’s arithmetic example illustrates information preservation. The result alone does not identify the original inputs; retaining supporting information allows them to be identified. The example explains that distinction without describing NSATS circuitry. Its retained output includes both the result and the supporting input.

For a gate that retains information, the state before an operation includes both the arriving input and the information already retained. Afterwards, it includes the output and the updated retained information. The reversibility test covers that complete change.

What an evaluation can check

White Paper 1’s assessment protocol provides a framework for a licensee’s evaluation of task completion, retained information, data movement and security. The organisation sets its acceptance criteria according to the intended use, with conclusions tied to the configuration and data examined.

A calculated result must also reach the application or person who will use it. The task is complete when the receiving application has the required information and can use it. A record of calculation time alone leaves storage and transfer work unaccounted for. Submitting a request does not establish that its output is available; the calling program distinguishes a completed request from one awaiting completion or one that failed.

The resource account separates retained storage, working RAM, retained gate information and the processor’s working memory. Carrying out a computation reversibly while saving its input requires processing time and storage space. An assessment therefore includes the work of retaining and accessing supporting information, alongside the operations that use it.

A regenerated input must be available to the component performing the later calculation when that stage begins. The design distinguishes it from values belonging to other runs or stages, and keeps values available while dependent work needs them. In an ordinary application, the meaning of an input includes its units, the item it describes and the conditions under which it is valid.

Retained earlier inputs need protection alongside current inputs and results in the licensee’s security assessment. Recovering information and protecting it impose different requirements: confidentiality concerns who can obtain it. Invertibility alone provides no secrecy. Protection depends on the cryptographic construction, appropriate key handling and the threat against which it is evaluated.

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips.

NSATS licenses its intellectual property: patents, designs and copyrighted software. Where the licensed IP takes the form of software, NSATS supplies it under the licence, with its documentation and updates. Each licensee designs and builds its own solution.
