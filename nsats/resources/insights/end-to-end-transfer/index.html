Reading an end-to-end transfer: when is it complete?

The decision

A network transfer serves the application that needs the information. An assessment therefore follows the work from preparation at the sending system through network movement and reconstruction to use at the destination. Application data and traffic on a connection are related views of the same work, but their records can refer to different stages.

NSATS’s networking architecture places a quantum-classical network card containing a quantum-classical chip at each endpoint. The sending card handles processing associated with preparation and transmission; the receiving card handles receipt and reconstruction. Data passes through ordinary routers between them. There is no NSATS chip in those routers. Routing uses addressing information to forward traffic, while the connected applications interpret the collection.

Each card also needs a connection to its host, the computer containing it. Integration connects the card’s work to memory, software and existing data paths. The implementation covers both endpoint systems and compatibility with the ordinary equipment along the route, including wired, optical or wireless links.

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips.

NSATS licenses its intellectual property: patents, designs and copyrighted software. Where the licensed IP takes the form of software, NSATS supplies it under the licence, with its documentation and updates. Each licensee designs and builds its own solution.

Completion

Completion is the point at which the receiving application can use the information. Arrival at the equipment and delivery to the program are distinct events. In ordinary packet networking, a collection can travel as separate pieces rather than as a single application object. A record of arriving traffic can therefore describe an earlier stage than the application’s record of a completed collection.

The sending application identifies the information and collection version to send, then submits its request through the host’s networking software. A request can be accepted while work continues. The software interface defines requests and their outcomes separately from the physical connection carrying traffic out of the equipment.

At the receiving end, the host associates incoming information with the application that requested it or is permitted to use it. That application interprets the information according to its task and data format. Its connection to the card is part of the transfer path, alongside the network connection between computers.

A completed transfer alone does not establish that the requested information was received. The check records the collection requested, the collection received and the application event marking completion. An integration check examines whether the application recognises the completed request and takes the required next action. The implementation description also specifies how each application should behave when an exchange fails or is interrupted.

The four measures

The measures describe different parts of the path to usable original data:

  • Channel capacity — the maximum rate of reliable information transmission under a channel model.
  • Transmitted-bit rate — bits sent on a particular link per unit time.
  • Original-data throughput — original data delivered per unit time.
  • Elapsed time to usable data — time from the start of the transfer task until the receiving application can use the data, including endpoint work.

Channel capacity and transmitted-bit rate describe the link; original-data throughput and elapsed time to usable data describe usable original data at the destination. Evaluation includes sending, network transfer, receipt, reconstruction and the internal data path at each endpoint. The measurement record identifies the sender’s preparation state at the start and the receiving application’s state when timing ends.

A comparison uses a defined dataset, a stated baseline and the same operating conditions. The organisation sets acceptance criteria for the intended use and keeps conclusions tied to the configuration and data examined. Repeated observations record failures and configuration changes as well as successful completion.
