Partners and collaboration

A useful collaboration brings complementary contributions to a defined technical or application goal. NSATS licenses technology in two separate portfolios, Quantum and Geomagnetism. This page sets out the current Quantum partnership priorities, followed by the collaboration routes that apply to both portfolios.

Current partnership priorities

Within its Quantum portfolio, NSATS is currently seeking three groups of partners: manufacturers of storage devices, LAN and other network interface cards, and RAM, together with designers of memory controllers; data centre operators, high-performance computing (HPC) centres, and data-hosting and web-hosting providers; and browser developers and other application providers.

Manufacturers develop hardware that incorporates licensed technology. Service providers deploy, in their own infrastructure, implementations built by licensees. Browser and application providers protect their users' information with licensed post-quantum security.

NSATS licences enable classical devices to perform operations based on quantum mechanics, at room temperature. The technology is developed and available under licence, and each licensee determines how it is incorporated into its equipment, systems and services. NSATS works with partners through technology licensing to develop quantum-classical applications.

NSATS's Quantum technology is already licensed under signed agreements, including in these areas, and NSATS is seeking further partners.

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips.

Storage, network and memory manufacturers

NSATS seeks manufacturers with the engineering capability to incorporate licensed technology into storage, networking and memory products. Manufacturers contribute component design, production, system integration and product qualification. The technology enables greater effective storage capacity, faster data movement and more efficient use of memory.

The quantum-classical bus carries electrical signals with more than two states, beyond binary 0 and 1. The bus enables faster processing, data transfer and decision making within a quantum-classical electronic device.

These implementations use specially designed classical chipsets and controllers built by the licensee. Existing drives and RAM always work through this added hardware as part of the licensee's integrated design. Each manufacturer determines how the licensed components connect to the rest of its design and how controller and firmware functions are maintained after the product is released.

Storage device manufacturers

The storage priority covers hard drives, solid-state drives, USB flash drives, optical storage and other storage devices. Collaboration develops temporal-drive implementations across these storage types. The licensed technology increases effective storage capacity, so more data can be stored within a given physical storage resource. The device's physical size stays unchanged; the complete implementation delivers the effective capacity.

In these implementations, classical data is encoded using quantum-mechanical logic. Reversible computing contributes to compression, so the device holds more data. For every storage type listed, the licensee-added chipset or controller manages intermediate storage and retrieval operations. Any increase depends on the storage device, how the licensee uses the technology and where the licensed gates, buses and computational technologies sit in the licensee's design.

Effective capacity depends on processing time, not only physical size. A temporal drive is better described by how much data it can process and store per second than by a fixed capacity.

This description of a temporal drive's rating applies across the storage types above. A licensee's evaluation should report the processing rate separately from the amount of data retained and retrieved intact. It should examine data integrity, reliability and compatibility across representative workloads and types of data. NSATS welcomes manufacturers able to integrate controllers, characterise storage and retrieval behaviour, and carry out these evaluations.

LAN card and network interface manufacturers

NSATS seeks manufacturers of local area network (LAN) cards and other network interface cards to develop quantum-classical networking implementations. Quantum-classical network cards at both ends of a connection enable high-speed data transfer, with data passing through ordinary routers in between. An implementation therefore covers both endpoints and the complete transfer path.

Relevant capabilities include network interface design, host integration, driver development and testing in the intended network environment. Evaluation should consider processing at each endpoint, compatibility with ordinary equipment along the path, including switches, routers and firewalls, and the time taken to make information usable by the application at the destination.

Quantum-Classical Networking →End-to-end path →

RAM manufacturers and memory-controller designers

NSATS seeks RAM manufacturers together with designers of memory controllers. Existing classical RAM holds classical data encoded using quantum-mechanical logic, so computer buses can send and retrieve it faster. The licensee's specially designed chipset or controller manages this, and less memory is needed for the same data within the implemented system.

In many computers, the memory controller sits in the processor, a system-on-chip, a chipset or a memory-module component rather than in the memory devices themselves. Controller designers therefore form part of this priority alongside manufacturers of the RAM itself.

Collaboration addresses controller integration, access latency and bandwidth, data integrity and the relationship between memory and the processor. Access latency describes the delay in obtaining requested data; bandwidth describes the rate at which data can be transferred. Evaluation should distinguish working RAM, which serves active computation, from retained storage, which holds data for later use. Each has different capacity, access and reliability requirements.

Data centre, HPC and hosting service providers

NSATS seeks data centre operators, HPC centres, and data-hosting and web-hosting providers interested in deploying implementations built by licensees, including manufacturers and integrators. Service providers contribute the workloads, infrastructure and service requirements against which an implementation can be evaluated in its operating environment.

With the licensed technology, fewer hard drives and less memory are needed to store data, existing memory processes existing binary data faster, and the chipsets run with lower heat than conventional computing. The extent depends on the deployed design and workload. Storage, working memory and network performance should be assessed separately to establish how each affects the complete service.

For data centres, evaluation covers storage and memory integration, compatibility with existing systems, and power and thermal behaviour. Chipset heat, server power and facility cooling should be measured separately, because a change in one does not by itself determine the others.

HPC centres can examine memory access, data movement between computing resources and the time needed to complete representative computational workloads. Hosting providers can assess application responsiveness, data availability, isolation between customers' workloads and continuity during infrastructure changes. Web-hosting providers and website operators also run the server side of the browser security software described in the next section.

A provider's evaluation should define a representative use case and compare the implementation against an established baseline, holding the application task and service requirements constant. Measures should cover physical storage, working memory, processing time, energy use and reliability. The assessment should use the kinds of data the service actually holds, including data that is already compressed or encrypted, together with the provider's knowledge of its operating environment.

Browser and application providers

NSATS seeks browser developers and other application providers to protect their users' information with licensed post-quantum security. NSATS's post-quantum security uses classical computing methods inspired by quantum mechanics to address the future threat that quantum computing poses to the public-key cryptographic methods widely used to protect communications and authenticate information. A complete design must also address classical threats.

For browsers and the servers they connect to, NSATS licenses its post-quantum security as software under standard software licence terms. For larger systems, licensees build the security into their own chips. The priority covers data in motion (data in transit), while it travels between systems, and data at rest, while it is stored.

To protect data travelling between a browser and a website, the licensed software runs at both ends: in the browser and on the server. Protecting the connection therefore involves both the browser developer and the operator or hosting provider of the server, each running the licensed software.

Data at rest includes information retained on the user's device. Its protection depends on how keys, permissions and access to the information are handled where it is kept. A browser's role therefore needs to be considered alongside the operating system, servers and storage involved. For other application providers, the scope may include client software, service interfaces, server-side processing and stored application data. Discussion can establish whether the software solution or a chip-based implementation for a larger system fits the application.

NSATS seeks partners with expertise in security architecture, key management, deployment and operation of security software across browsers and servers, and independent security assessment. Security architecture concerns how protection is organised across a system; key management concerns who may use keys, where they are held and when their use is withdrawn. A collaboration should define the information to be protected, the relevant quantum and classical threats, and the responsibilities of each component. Assessment should ask how the licensed security operates within the complete system and how it relates to the standards, protocols and certificates on which the application already relies.

Security needs to be reviewed and kept up to date as threats, standards and application requirements change. Partners should plan how updates, interoperability and migration will be handled within their deployment, alongside performance and usability.

Software and hardware implementation

An implementation proposal should identify the function to be developed and its place in the wider system. Software, electronics and integration work may contribute at different points, with responsibilities defined around the needs of the application.

In an ordinary system, software issues requests while electronics carry out device operations; integration work establishes how a request passes between them and how the result returns.

The Quantum implementation page covers software and hardware choices; the Geomagnetism implementation route concerns the equipment and application that receive a position output.

Application evaluation

An organisation with a practical use case can help define the operating context and the questions an evaluation should answer. Describe the task, relevant conditions and the information needed to decide whether the approach is useful.

The evaluation questions above address the current Quantum priorities; other practical use cases in either portfolio can also be discussed.

Who works with NSATS, and how

A licensee takes a licence and builds an implementation. For browser security, a licensee instead takes a software licence and runs the licensed software in its browser or on its servers. An implementation collaborator contributes software, electronics or integration work. Researchers investigate a computing or positioning question, while suppliers provide goods or services to NSATS.

Use the licensing and collaboration routes for the first three roles. Suppliers can start with Vendors, Suppliers and Procurement.

The supplier route guides an organisation introducing its capability and preparing for a supply engagement, while the licensing route concerns permission to implement technology.

A service provider deploys an implementation built by a licensee in its own infrastructure and, for browser security, may run the server side. Service providers use the partnership route.

Propose a collaboration

Summarise the intended outcome, your contribution and the work you would like to explore with NSATS.

For a discussion about the current partnership priorities, outline:

  • Your area of work: storage devices, LAN or network interface cards, RAM or memory controllers, infrastructure services, browsers or other applications.
  • The product, system or service concerned.
  • Your intended role: licensee, implementation collaborator or service provider, as defined above.
  • The capabilities, integration resources or operating environment your organisation would contribute.
  • The workload or security requirement, existing constraints and criteria for evaluating the result.
