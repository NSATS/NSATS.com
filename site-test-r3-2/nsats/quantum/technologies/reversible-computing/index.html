Reversible Computing

Reversible computing allows a calculation to be traced back to its original input. NSATS’s quantum-inspired logic achieves reversible computing in classical machines, going beyond simulating quantum-mechanical behaviour: data is retained within the circuit, so the input can be recovered from the output. The technology is designed for lower energy use and allows earlier information to be reused in further processing.

Reversing a calculation

A reversible operation allows its input to be determined from its output. Multiplying a number by a fixed value of two is a simple mathematical example: dividing the result by two returns the original number. The forward and reverse operations form a pair.

Adding three and seven gives ten, as does adding four and six. To identify the original pair, more information is needed than the total. If the total and one original number are retained, subtraction can identify the other. This illustrates the role of retained information in reconstructing inputs.

Reversing a mathematical operation requires knowing which operation was performed and any parameter that defined it. A value on its own does not describe the calculation that produced it. The range of allowed inputs also matters: it determines which candidate inputs belong to the problem being solved.

Retaining the information needed

Three approaches provide earlier information:

  • Direct inversion.
  • Retained supporting information.
  • An explicit memory record.

An ordinary internal bus carries data and requests between components; a request identifies the information and action needed by the receiving part.

The relevant distinction is what can be determined from a result and what additional information has been kept. Retained information needs to be held and supplied when required, with consequences for storage, access and processing. NSATS’s technology retains the data within the circuit alongside the operations that reconstruct earlier inputs.

The device’s internal connections, including the quantum-classical bus, supply that information. The bus carries electrical signals with more than two states, beyond binary 0 and 1, enabling faster processing, data transfer and decision making within a quantum-classical electronic device.

Ordinary software can associate supporting information with a result through a record identifier.

Reusing earlier information

NSATS’s processing relationships include forward calculation, reconstruction of an earlier input and use of that reconstructed information in further computation. This allows an earlier input to become the starting point for a subsequent calculation.

The purpose of reconstruction is therefore to make information available for continued work. The design accounts for both the reverse operation and the handover of its result to the next part of the computation.

An ordinary program may reuse an earlier value under changed parameters. The value and its context are separate inputs: the program needs both the quantity and the meaning attached to it. Units and the item being calculated can be part of that context.

Reuse also has a lifetime. A program may need a value until all dependent work has finished, even after the operation that first produced it is complete. The surrounding software must distinguish a value still needed by another stage from one whose use has ended.

Energy use in computation

The physics of computing links irreversible information erasure with energy dissipation. This is one reason to study reversible operations: preserving information can offer a route to computation with less dissipation. Practical energy use depends on how those operations are implemented and how the system handles memory and data movement.

In an ordinary calculation, logical erasure occurs when distinctions between earlier inputs are discarded, leaving a result that cannot identify which input was used. It concerns the information preserved by the operation, not simply whether a file has been deleted. The physical process of irreversible erasure is associated with energy dissipation as heat, which the equipment must release to its surroundings.

NSATS’s quantum-inspired logic for reversible operations is designed for lower energy use, and its gate designs increase chipset speed. A licensee’s evaluation should consider the complete task, including the processing and memory operations needed to retain, reconstruct and reuse information.

Power describes the rate of energy use; energy describes the amount used over an interval. A complete computing task includes periods of active calculation and periods when components wait or exchange information. An energy assessment needs a defined interval and a defined set of components, so that the measured energy relates to the completed work.

Applications

High-performance computing

In a sequence of scientific or engineering calculations, a later stage may need information used earlier in the task. Reversible computing provides a way to recover that earlier input for further processing. NSATS’s quantum-inspired logic supports high-performance computing and new computing platforms built on reversible computing, carrying out computational work more efficiently, faster and with lower energy use.

In an illustrative engineering calculation, a program uses a component’s original dimensions and material properties to calculate its response to a load. A later stage examines another load case using those original inputs. The intermediate response is specific to the earlier case; the dimensions and material properties remain inputs to the new calculation. The task therefore distinguishes reusable source information from results tied to particular conditions.

Implementation and licensing

A licensee can incorporate reversible methods into software, programmable hardware or a custom chip design. The intended task determines where operations take place, what information is retained and how it is supplied to later processing.

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips. A licensing discussion can focus on the calculations an intended system needs to perform, its memory requirements and its energy priorities.

A licensee can describe the calculation’s inputs, the result required at each stage and the earlier values that later stages request. It can identify where the surrounding program expects those values and the format and units in which they are used.

Equipment constraints, existing software interfaces and inputs with expected outcomes can accompany the licensee’s task description. An evaluation plan can then distinguish checking the forward calculation, checking the earlier information supplied for reuse and measuring the resources used by the whole task. Each check needs an observable outcome defined by the application.
