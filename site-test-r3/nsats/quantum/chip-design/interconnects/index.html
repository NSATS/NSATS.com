Internal buses and interconnects

Internal buses and interconnects move data among the components of an electronic device. NSATS’s connection and transfer processes speed up those exchanges and support applications that depend on them.

What an internal connection carries

An ordinary digital bus uses binary signals to exchange data and requests between device components.

In ordinary devices, an interconnect is the connection arrangement through which components communicate. A shared bus provides a path used by several components, while a point-to-point connection joins a particular pair. These are ways of arranging communication paths; the application’s required exchanges determine which components need to communicate.

A processor may request working data from memory, send results to another component or pass information to a network interface. Each exchange is part of the device’s work. The connection has to serve both the component supplying the information and the component that will use it. The quantum-classical bus carries electrical signals with more than two states, beyond binary 0 and 1, which enables faster processing, data transfer and decision making within a quantum-classical electronic device.

In ordinary software, context identifies what a received value means and which task uses it. The meaning of the exchange belongs to the agreement between the components.

A system description should distinguish the information an application wants from the information exchanged to obtain it. A request can carry identifying information even when its eventual result is a large collection.

Movement and coordination

Fast data movement is useful when it helps the receiving component continue its task. NSATS’s technology treats internal transfers alongside processing, memory access and coordination between components. Relevant questions include the time taken for an exchange and the amount of useful data the path can carry during the task.

Coordination concerns when information is needed in relation to the work already under way.

In ordinary software, work can be ready to run but still wait for a component it needs.

Software waiting for a memory operation needs to distinguish an accepted request from a completed one.

Useful data is the information transferred for the application’s work. The total moved can also include addressing, control information and repeated transfers, which are overhead associated with carrying that useful data. An assessment of a path should distinguish the application information delivered from all the traffic needed to deliver it.

Several tasks can make demands on the same surrounding system. Their exchanges may occur together or depend on earlier work finishing. An assessment should state which tasks are active, what information each requests and which responses must arrive before it can continue. These workload conditions apply even where the calculating operations are unchanged.

Applications

A calculation waiting for an individual item depends on the response to that request. Work organised around a collection instead raises questions about moving the information needed for the next stage.

Scientific calculations, data analysis and embedded devices can all involve repeated transfers among components. The appropriate design depends on the application’s pattern of work: frequent small exchanges raise different questions from larger transfers. These patterns provide a practical starting point for considering licensed connection and processing methods.

In an illustrative inspection device, a camera supplies a collection of observations while control software requests an individual equipment setting. The analysis consumes the observation collection, and the control task needs the setting before deciding its next action. The exchanges serve different purposes and can occur while the same device is working.

For that illustrative device, counting transferred data alone does not show whether the analysis and control tasks received what they needed.

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips.

A licensee can describe how requests are distributed across a task: which occur repeatedly, which carry collections and which must finish before other work begins. It can also identify the components already present in the equipment and the interfaces they expose.
