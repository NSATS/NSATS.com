Geomagnetism demonstration

Follow a positioning run and connect a location to an inspection finding, a robot's task or an asset event. Select a moment in the run to read the position supplied, the time it belongs to and the application record associated with it.

Interactive illustration. The locations, times and application records are examples. This walkthrough uses no connected magnetometer and does not request your browser's location.

How to use the demonstration

  1. Choose a scenario and read its task.
  2. Select an event, or use Next event to move through the run.
  3. Read the positioning output alongside the example application record.
  4. Check the location's original time, especially when the display retains a last-known position.
  5. Complete the task and use the takeaway to identify what you would need in your own application.

Play advances through the example events. Pause holds the current event. Stop ends playback and leaves the current event available to inspect; Restart returns to the first event. Playback progress is separate from the measurement times written in the example records.

What the array measures

Geomagnetic positioning determines location using Earth's magnetic field and supports positioning without reliance on live GPS satellite signals. The field's strength and direction vary with location. Measurements at a device also include disturbances associated with its surroundings, including nearby iron objects, machinery and electrical installations.

The specified demonstration arrangement connects NSATS software to a custom magnetometer array connected to novel antennas and DSP chips. Incoming data come from an array of at least eight chips. A measurement channel is a stream of measurement data; the number of channels depends on the arrangement and is not assumed to equal the number of chips.

The illustration shows channel availability without assigning a channel count. Its availability panel tells you whether measurements are arriving, while the position output and application record answer different questions about the event.

From measurements to a location

The journey begins with measurements from the array. Multiple filters and NSATS's proprietary digital signal processing prepare the incoming data for positioning. NSATS's positioning method determines a location, which the application can display and associate with a task or observation.

Read the four stages in order: Measuring → Filtering and DSP → Position output → Shown and recorded. They describe the role of each stage. In a licensee's implementation, the division of work between software and hardware depends on the device design.

The resulting location gives an application a place. The application supplies the meaning of its own event: a technician reports a damaged bracket, a robot receives a task, or a logistics system records a handover. Selecting an event lets you inspect those two contributions together.

Reading the display

The site plan gives each example location a context, such as a fitting, warehouse bay or handover gate. The text location record provides the same location label and the time of the selected event. It separately gives the original time of the position shown, alongside the measurement and display states. You can complete the task using the text record alone.

A position from the selected event and a retained last-known position have different labels and marker styles. An event marker identifies the associated application record. Route travel and inspection records are also shown separately: travelling past a fitting does not establish that it was inspected.

For each event, read Positioning output first, then Example application record. A note about a repair, a task transfer or an observed condition belongs to the application record. Keep that note associated with the position and time it actually has.

Three questions about each event

FieldQuestionExample values
Input availabilityWere measurement channels delivering data?All channels reporting; some channels not reporting; no channel data.
Position outputWas a new position supplied for this event?New position supplied; no new position.
DisplayWhich position is being shown?Position from this event; last-known position with its original time; no position shown.

An application event without an associated measurement record, such as a task transfer or handover, has no input-availability or position-output values of its own; read the surrounding measurement events for location context.

Read these fields separately. Measurements arriving and a new position being supplied are different events. A displayed location may also belong to an earlier event, so its original time remains visible.

When no new position is supplied, an application can retain a labelled last-known position or clear the location display. The optional status exercise shows both choices and identifies the rule used by the example application. It records the supplied state without inventing a reason for it.

Location and reference

The main location record represents geomagnetic positioning output. It can be displayed on a site plan or map, with the same information available in text. The example plan uses named places to make each task easy to follow.

A separately supplied reference position can support an evaluation. If a satellite GPS reference is included in a recorded evaluation, it needs its own source and label so that readers can distinguish it from the geomagnetic output. The current illustration has Reference: None.

Scenarios

Each scenario is an illustrative application task. Choose Explore this scenario to open its events and task instructions.

Find the tunnel fitting that needs repair

An inspection technician passes similar fittings along a tunnel. The application records an inspection of fitting F3 with no finding, followed by a damaged bracket at fitting F4. Work stops at an obstruction before the planned route is completed.

Select the F4 finding and read its location, time and repair note. Then review the exit event and separate the route travelled from the fittings recorded as inspected. Choose What if no new position arrives here? to explore the alternative. The display then keeps F3's position with its original time because no new position was supplied at the F4 finding. Decide what additional identification the technician would need to associate the finding with the correct fitting.

The task ends when you have examined the finding and the exit record. Its lesson is that a location supports an inspection record, while the record establishes what was actually inspected.

Read a warehouse robot's task record

A warehouse robot records damage at aisle C before reaching a job that has been transferred to another robot. Its final return event retains the last-known position. These events combine a location history with decisions recorded by the warehouse application.

Start with the fault report, then read the task-transfer event and the instruction at the destination. Finally, inspect the return event and its position time. You should be able to distinguish the place associated with a fault, the application decision assigning work and an earlier position still visible on screen.

The task ends after you have read the fault and return records and explained the transferred job. The location record gives operational context; the application log explains the task.

Locate an asset handover

An asset history contains regular position records together with receipt, bench inspection and handover events. Use the event filter to find the handover, then compare it with the surrounding interval records.

Switch to the second asset history. Here, the handover is an application event between position records and has no position of its own. Read what the log establishes about the event and what location information is available around it. Keep the handover time separate from those earlier and later measurements.

Complete the task by examining both handovers. The comparison helps you decide when your own application needs a position associated directly with an event, alongside its regular location history.

Review the phases of a subsea inspection

An example subsea mission has deployment, transit, inspection and return phases. Observations at an inspection hold belong to one phase, while an interval without new position output appears on the return journey.

Select each phase to read its associated observations and available positions. During the return interval, inspect the retained location and its original time. Bring the phase summaries together to identify which work has an associated location record and where the position history has a gap.

Finish after reviewing every phase and the return gap. The task shows how a mission record can organise positioning and observations by work phase, with missing intervals kept visible.

Explore this scenario →Marine and subsea applications →

Identify the visit associated with a route finding

A rail maintenance crew visits the same loading bay on its outward and return legs. A finding belongs to the return visit. Select the two stops and compare their location, time, leg and application record.

Choose Compare positions only to view the shared place without the details that identify either visit. Then restore the visit details and associate the finding with the correct event. The comparison asks a specific question: does a place alone identify the visit you mean?

Complete the task by selecting the return visit and explaining which details distinguish it. For repeated routes, the event's time and application context are part of a useful location record.

Separate an aerial platform's location from its observations

An example inspection aircraft holds beside a bridge pier while observations describe different sides of the structure. Several observations share the platform's location; one uses a clearly labelled last-known position.

Select the observation records and read the subject identified in each. Compare that subject with the aircraft's location and original position time. The observation's label identifies what was examined, while the position record describes the platform carrying the equipment.

Finish by examining all three observations and identifying the one associated with an older position. The task helps you keep platform location, observation subject and event time distinct in an inspection record.

Practise reading the status fields

This optional exercise focuses on the display itself. Step through new position output, a retained last-known position, a cleared display and a return to new output. Read input availability independently at each event.

Compare the example application's choice to retain a position with its choice to clear the display. Finish when you can identify the location being shown, its original time and the application rule in use. This exercise is useful before reviewing an event history with gaps.

Evaluating an implementation

Begin with the task your device must support. Specify what a useful location record needs to contain, how its time is associated with an application event and what the application should do when a new position is unavailable.

An evaluation also needs the device arrangement, operating conditions, measurement records and any separately supplied reference. Those details give a result its context. Preserve the original acquisition times and the distinction between a supplied position, a retained position and an application event.

Using positioning in your device

NSATS's geomagnetic positioning technology is developed and available under licence. Licensees incorporate it into their own chips, embedded hardware, devices and systems, and decide how its output is used by the application.

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips.

For an inspection device, the integration question may be how to attach a position to a finding. For a robot or asset system, it may concern the relationship between a task event and a location history. The SDK design documentation provides a starting point for considering measurement collection, processing and the information exchanged with an application.

Questions

How accurate is the location?

The illustration uses authored locations, so it does not measure positioning accuracy. Assessing accuracy requires matched reference data and a defined evaluation method. Read the evaluation methods and readiness guidance for the information needed to assess an implementation.

Are disturbances errors?

Not automatically. Magnetic measurements include contributions from the surroundings, such as nearby iron objects and electrical installations. Those contributions form part of the measured magnetic environment. Read about operating environments for the context an evaluation should record.

Is the location displayed as GPS?

It is a geomagnetic location display: a site plan or map paired with a text record. Any separately supplied satellite GPS reference has its own label.

Why is an earlier position still visible?

The example application has retained a last-known position. Read its original time and the separate position-output field to distinguish it from a new position at the selected event.

Does a stop mean the place was inspected?

An inspection entry establishes what the technician examined. A stop or route trace provides location context. In the tunnel scenario, only fittings with inspection entries count as inspected.

Are the measurement channels the chips?

The specified arrangement contains at least eight chips. Channels describe measurement data streams; their relationship to the chips depends on the device arrangement. The current illustration therefore shows availability without a numbered channel layout.

Can I follow the task without using the site plan?

Yes. The text location record, event list and status fields contain the information needed to complete each task.

Where should I go after the walkthrough?

Use the application link for your scenario, then read the evaluation and integration guidance. These help turn the task you explored into questions about your own implementation.
