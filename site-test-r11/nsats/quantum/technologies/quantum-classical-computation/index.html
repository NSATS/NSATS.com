Quantum-Classical Computing

NSATS licences enable classical devices to perform operations based on quantum mechanics, at room temperature. The technology operates without super-cooling. NSATS’s technology applies computational ideas drawn from quantum mechanics in specially designed classical chipsets. It includes quantum-inspired gates for reversible computing, memory and processing, delivering lower energy use, greater usable memory capacity and faster processing of computing tasks.

Quantum-inspired gates

A gate defines an operation on information. Gates can be combined to perform a calculation, which can then form part of a larger computing task. NSATS’s quantum-inspired gate designs use selected computational relationships from quantum mechanics in these operations and increase chipset speed.

In ordinary digital logic, an electrical signal stands for a logical value. A gate applies a rule to its input values to determine its output. For example, a rule can require a combination of inputs to be active before the output becomes active. A circuit’s connections determine which output supplies which later operation, so changing a connection can change the calculation even if the individual gate rules stay the same.

One use is reversible computing: operations that preserve the information needed to reconstruct earlier inputs. Another concerns how information is represented for storage and use in memory. These uses affect the information an operation receives, the result it produces and what remains available for subsequent work.

In a digital calculation, several chains of operations can contribute to the result. Stages whose inputs are ready can be arranged to proceed independently; a stage waiting for an earlier result remains dependent on that result.

Reversible calculations

Working backwards through a calculation requires enough information to identify its earlier inputs. Some operations have a direct inverse; other approaches retain supporting information alongside a result or in memory. NSATS’s technology does more than simulate quantum-mechanical behaviour: it achieves reversible computing by retaining data within the circuit, so an output can be traced back to its input and the input recovered from the output.

In an ordinary program, a result such as a category or a rounded value may correspond to several original inputs. The result alone cannot distinguish them. Supporting information might be a saved input or a record of the choice made during the calculation. It belongs to the program’s data and must remain associated with the particular result it describes.

In NSATS’s processing relationships, an earlier input is recovered and used as the starting point for a later calculation. The system design needs to retain and supply the information required for that step.

The recovered input must be available to the component performing the later calculation when that stage begins.

A program can overwrite a variable as it proceeds. If a later operation needs the earlier value, the design must provide a retained copy or a way to derive it from information still available. Keeping the right value also means distinguishing it from values produced by other runs or other stages of the same task.

Memory and data movement

The information needed by a calculation must be held somewhere and supplied to the component performing the work. A computing design therefore accounts for both the operation and its access to data.

In an ordinary computer, a file on a drive and the values being used by a running calculation occupy different parts of the system. A program can load the relevant part of a file into working memory rather than keep the whole collection active. A processor may also keep frequently used values in local storage close to its operations.

Temporal compression increases effective capacity: more data can be stored or retrieved on the same drive. Effective capacity depends on processing time, not only physical size. A temporal drive is better described by how much data it can process and store per second than by a fixed capacity. The drive’s physical size stays unchanged. Classical data is encoded using quantum-mechanical logic, and reversible computing contributes to compression.

The increase depends on the drive, how the licensee uses the technology and where the licensed gates, buses and computational technologies sit in the licensee’s design. For both existing drives and RAM, the licensee adds a specially designed classical chipset or controller built with the licensed technology. It encodes the data and manages the intermediate operations when information is stored or retrieved. The drive or RAM itself remains ordinary classical storage. This is not a software-only upgrade or a drop-in change; integration is part of the licensee’s design.

An ordinary digital bus carries signals for data, addresses and requests between components. The address identifies the information being requested; the request tells the receiving component what action is needed. Digital logic in ordinary electronics interprets binary signals as logical values. The physical connections and the rules for exchanging those signals form part of the system’s interface.

Through the licensee-added chipset or controller described above, existing classical RAM holds classical data encoded using quantum-mechanical logic, so computer buses send and retrieve it faster. Data-movement technology handles transfers between the components using it. The quantum-classical bus carries electrical signals with more than two states, beyond binary 0 and 1. This enables faster processing, data transfer and decision making within a quantum-classical electronic device. Computing operations, holding information and moving it are different responsibilities within the same task.

Applications

Applications span demanding calculations and computing built into equipment.

High-performance computing

A scientific simulation may require a long sequence of calculations. This makes the operations used to perform those calculations an important design choice. NSATS’s quantum-inspired gates support reversible processing in classical machines and new computing platforms using reversible computing, improving completion time and energy use across the intended task.

In an illustrative simulation of heat spreading through a material, the program tracks temperatures across a model and repeatedly calculates how they change. The current values are inputs to the next update, while selected results may be kept for analysis. The work includes updating the model and passing values between dependent calculations, rather than simply repeating an isolated arithmetic operation.

Embedded and edge systems

An industrial controller or local data-processing device must carry out its assigned functions within limits on power, space and cost. NSATS’s computing methods support the division of those functions between software and chip logic. The application determines which operations belong in hardware and how they obtain the information needed to work.

In an illustrative temperature controller, the device reads a sensor, compares the reading with a setting and decides whether to operate a heater. Its computing hardware shares an enclosure and power supply with the equipment it controls. A designer must allow for the heat produced by the electronics, the space taken by connections and the need to change control settings or behaviour.

Software and chip implementation

A licensee can implement a computational method in software, programmable hardware or a custom chip. Software carries out functions through a program. Programmable hardware allows selected functions to be configured in hardware logic, while a custom chip incorporates them into a dedicated design.

Updating a software function usually involves changing its instructions, while altering programmable hardware involves changing a logic configuration. A function fixed in a custom chip may require a revised chip design to change that behaviour. The choice therefore includes how the function will be maintained after deployment and which parts of the system must continue to work with it.

The application determines how these choices fit together. Processing functions need access to the relevant memory and connections, whether they run in software or hardware. Performance evaluation should therefore consider the complete task, including the time and energy used to process and move its data.

A component with a specialised function still exchanges requests and results with the rest of the application. Those exchanges have a format and an expected sequence. Integration testing can check that both sides interpret a request in the same way and agree on when the requested work has finished.

IP licensing

NSATS sells technology licences, not chips. Its technology helps licensees manufacture their own chips. Licensees build the software, chips, devices or systems. A licensing discussion can start with the task you want to perform, the system in which it would run and the requirements that matter most.

Describe the input, the expected output and the equipment that will use it. Existing software interfaces and hardware connections are constraints on a new function. A licensee can distinguish the behaviour it needs to preserve from features it can change, and specify how it will check that the completed implementation performs the intended task.
